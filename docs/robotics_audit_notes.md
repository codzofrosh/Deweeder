# Phase 0 robotics and QA audit notes

Scope: read-only review of `deweeder_tertill` ROS 2 core, messages, HAL, scripts and packaging, 2026-09-14. No hardware, ROS graph, simulator, transport, or actuation commands were run. Paths below are relative to `deweeder_tertill/`. Findings describe checked-in source, not measured robot behavior.

## Blocking defects

1. **Behavior cannot import.** `src/weedbot_core/weedbot_core/behavior_node.py:121` has an empty `_safety_cb`, immediately followed by another definition. Unresolved merge markers remain at lines 162, 208, 209, 216, 217 and 250. AST parsing all 25 Python files under this subtree reports an indentation error at line 122; the other 24 parse. Resolving markers alone will not restore safety reception.
2. **HAL cannot import in a ROS environment.** `src/weedbot_core/weedbot_core/hal_hw_gpio.py:40` defines `HalHW(Node)` without importing `Node`; imports at lines 21-28 do not define it. This is a static undefined-name finding; runtime was not attempted.
3. **Installation omits essential code and launch assets.** `src/weedbot_core/setup.py:10` lists only `weedbot_core`, omitting `drivers` and `hal` directories; line 17 installs only `launch/*.launch.py`, excluding `gz_bridge_launch.py` and YAML assets. Source-tree imports can conceal installation failure. Package manifest also omits direct imports/launch dependencies including `tf2_ros`, `rcl_interfaces`, `launch_ros`, `ament_index_python`, `ros_gz_sim`, `ros_gz_bridge`, and `robot_state_publisher`.

## Safety and actuation gaps

4. **Watchdog does not actively stop retained outputs.** `hal_hw_gpio.py:118` installs only a readiness timer; lines 125-126 merely store a new safety level. Heartbeat expiry is enforced only when new motion/tool messages arrive (155-195). If behavior dies, both heartbeat and commands cease: there is no subsequent driver stop call. A STOP arriving after the last command has the same problem. Driver `emergency_stop()` and `heartbeat()` exist in the interface but HAL never invokes them. Shutdown calls `shutdown()` without first stopping outputs (204-207); serial shutdown only closes the port (`drivers/serial_driver.py:91`). Hardware MCU watchdog behavior is unverified.
5. **Safety starts permissively and ignores stale inputs.** HAL starts with safety 0 and a fresh synthetic heartbeat timestamp (`hal_hw_gpio.py:79-82`). `safety_node.py` initializes normal state, republishes the last values, and has no sensor freshness deadline. Its tilt check at lines 94-119 examines angular velocity only: an overturned stationary robot can return to NORMAL. Emergency is not latched. These are design gaps requiring a defined fault/rearm contract before hardware use.
6. **Tool path is incomplete.** `hal_hw_gpio.py:186-200` gates front activation but forwards the original belly mode during STOP/stale heartbeat and never forwards `agitator_pulse`. None of the current drivers implement `apply_tool`; the optional `hasattr` silently skips actuation. Do not treat the declared `ToolCmd` fields as demonstrated tool control.
7. **Backend readiness is not live health.** `hal_hw_gpio.py:93` maps unknown backend names to mock; exceptions fall back to mock and may publish ready. `_driver_ready` is captured at initialization and never follows serial/CAN connection failure. `serial_driver.py:145-153` and `socketcan_driver.py:163-176` swallow send failures into internal flags. An init returning False does not enter the exception-only fallback, despite driver comments promising fallback. Mode, backend, fault, and physical readiness need separate states.
8. **Hardware feedback is not connected to ROS state.** Serial/CAN drivers cache encoders/current, but HAL never reads them or publishes `MicroSensorPacket`. Pinmap configuration is passed/stored without consumption. HAL directly commands only channels 0 and 1, while the template names four independent wheel channels. Physical channel mapping remains an unverified assumption.

## Control and simulation integration defects

9. **Odometry velocity is always zero.** `robot_state_node.py:131` updates previous encoder counts before lines 154-157 compute velocity deltas against those same counts. Position can advance while twist remains zero. Reuse the differential-drive pose integration after correcting timestamped delta handling and validating geometry.
10. **Simulation has multiple publishers and a feedback path.** `launch/gz_bridge_launch.py:91,98` publishes Gazebo `/odom` and `/imu`; `robot_state_node.py:69-70` publishes the same topics; `sim_sensor_bridge_node.py:66-67` subscribes to them and feeds packets back into robot_state. Consumers can alternate simulator truth and reconstructed values; zero reconstructed velocity can feed back into synthetic encoders. Separate raw simulator topics from estimated topics and assign one odom/TF authority.
11. **Full simulation launch lacks motion conversion.** The simulator consumes `/cmd_vel` (`gz_bridge_launch.py:89`), behavior publishes `/motion_cmd`, and the launch never starts `scripts/motion_bridge.py`. The mock HAL only stores PWM. That script is also absent from setup entry points. Its existing direct conversion bypasses HAL gating, so integrating it unchanged would not validate HAL safety.
12. **PID is diagnostic, not a motor feedback loop.** `motor_controller.py:168-180` treats cumulative counts as speeds, averages FL/FR as left and RL/RR as right (inconsistent with `robot_state_node.py:56,114-115`), ignores tick time and angular command, and publishes only text. HAL independently uses open-loop scaling. Readiness once enabled is not revoked when HAL reports False (134-137); timeout parameter is unused. Keep the PID helper as a candidate utility, not a claimed working controller.
13. **Coverage completion does not stop behavior.** The planner publishes a status string and stops heading publication on completion; behavior subscribes only to heading, retains its last value, and continues forward. Completion/abort must be an explicit command contract. Runtime verification is blocked by the behavior syntax errors.

## QA observations

- `scripts/watchdog_test.sh:28,33,38` starts duplicate HAL/controller processes because the core launch already starts both. Lines 67-77 inspect a log string, print FAIL without failing the process, and do not verify driver output. Killing behavior removes command callbacks, exposing finding 4.
- `scripts/test_safety_override.py:70,89,95` prints failures without assertions/nonzero exit; its injected safety publisher can race the live safety node. It checks behavior motion, not final driver/tool outputs.
- `scripts/safe_motor_ramp.py:10` publishes `/robot_state` sensor signals rather than motion setpoints; its name does not describe current semantics.
- `scripts/hw_smoke.sh:25` has no actual timeout around topic echo despite its comment. The command publisher can also compete with launched behavior. Final success does not establish output correctness.
- `scripts/spawn_robot.sh:19,24` suppresses spawn failure using `|| true`.
- `tests/test_hal_mock.py` checks basic mock operations, but does not assert zero output after stop, reverse encoder direction, watchdog expiry, tool interlocks, or transport health. Mock encoder counts increase using absolute duty (`drivers/mock_driver.py:46`) even when commanded reverse.
- `weedbot_msgs` is a useful small interface starting point. Messages lack timestamps, sequence IDs, units/enums and explicit validity; freshness must currently be inferred from arrival. The interface group declaration is nested inside `<export>` in its manifest and CMake force-sets a variable as a workaround; validate against the target ROS build system before claiming reproducible packaging.

## Reuse recommendation and next gate

Preserve the package split, message intent, backend interface, serial/CAN framing, differential-drive integration, coverage waypoint generator, and logging code as R&D assets. Treat backend transports and tool control as unvalidated prototypes. Prefer repairing a single explicit simulation-to-control command path over creating another parallel stack.

Before simulation acceptance: resolve syntax/import/installation defects; define topic ownership and command arbitration; test autonomous watchdog expiry and immediate stop against a recording mock; validate odometry with known signed encoder deltas; verify completion stop; run a clean installed ROS 2 workspace launch. Before hardware acceptance: separately establish verified electrical/channel mapping, MCU stop behavior, tool interlocks, freshness/rearm rules, and transport fault tests. This audit does not authorize or perform that hardware stage.
